## 1. 原版 Folo 存在的问题

在深入体验与逆向分析官方原版 Folo 客户端（参考 `folo_feature_limitations_analysis.md`）后，发现存在以下痛点与体验缺陷：

### 1.1 严格的商业化付费墙拦截
原版客户端将大量生产力功能（AI 全文摘要、文章翻译、多模型对话、时间线总结等）绑定在官方 Pro 订阅计划上。对于免费（Free）用户，即使仅仅是想使用客户端的基础功能，也会在各处触发 402 升级提示弹窗（如提示“开启免费试用以继续使用 AI 摘要，升级到 Pro 计划”）。

### 1.2 纯客户端功能的“伪付费”人为限制
代码审计表明，官方价格表中划归 Basic/Plus 以上的许多功能，**100% 运行在客户端本地，服务端完全未参与处理**，但原版前端代码通过硬编码的 `PAID_SETTINGS` 和角色判断，人为对 Free 用户进行了禁用：
- **全部第三方集成封锁**：包括 Readwise、Obsidian 本地 Vault 笔记写入、Cubox、Zotero、Instapaper、Outline、Readeck、Eagle、qBittorrent 以及自定义 Webhook，在 Free 账号下全部被置灰；
- **安全防盗链图片代理反向封锁**：防盗链代理在未登录时默认放行，但登录普通账号后反而被强制关闭，导致微博、Pixiv、小红书等特定防盗链图片在阅读时直接挂裂；
- **阅读隐私与偏好设置加锁**：隐藏文章下方最近阅读者、隐藏界面徽章、在时间线中隐藏私密订阅等纯本地偏好，普通用户无法修改；
- **私密订阅禁用**：订阅源弹窗中的“设为私密”开关被针对性 disabled。

### 1.3 BYOK (自带密钥) 功能不完整且缺乏自定义支持
- **无法自定义 Base URL**：原版仅预置了部分官方服务商，无法直接填入任意 OpenAI 兼容的第三方中转接口或本地私有化部署网关（如 OneAPI、NewAPI、Ollama、LocalAI 等）；
- **无法拉取与选择模型**：配置 BYOK 时无法配置或从远端服务端读取可用模型列表，用户无法自由选择实际调用的模型名称；
- **配置时崩溃异常**：进入部分包含 BYOK 设置或用量统计的界面时，因缺少防御性空值校验，容易抛出 `reading 'total' of undefined` 导致页面白屏崩溃。

### 1.4 官方云端依赖残留与静默降级暗坑
- 在原版代码中，部分 AI 请求（如 AI 摘要、标题生成）一旦遇到请求网络波动或参数不符，会在内部静默回退调用官方云端计费接口 `api().ai.*`；
- 一旦用户使用的是免费账号，降级调用立刻被官方服务器拒绝并返回 402 状态码，强行弹窗要求用户充值付费，导致本地配置形同虚设。

### 1.5 AI 对话模型选择器交互缺陷与 401 报错
- **死锁逻辑**：原版在可用模型数量只有 1 个时，直接跳过下拉菜单包装器（`hasMultipleModels` 判定为 false），导致用户点击模型标签毫无反应，无法切换或查看模型配置；
- **小窗口样式隐藏**：模型名称在小于断点（`@md`）的窗口或默认浮窗下被 CSS 强制隐藏（`hidden @md:inline`），仅残留极小图标，造成视觉上模型选择器缺失的困扰；
- **前缀比对失效致 401**：在模型匹配时未检索 `availableModels`，且带前缀的模型名（如 `openai/gpt-4o`）匹配失败后直接回退到数组首个 Provider 的密钥，导致请求向目标服务发送错误密钥，报出 `401 Invalid API key`。

## 2. 为什么 Fork 进行定制修改

本项目的核心理念是：**让开源 RSS 阅读器回归数据自主、阅读自由与智能自由**。

1. **摆脱中心化依赖**：用户应当有权使用自己的 API 密钥与自建算力，无需将阅读数据与提问上下文提交给官方托管服务。
2. **破除本地人为设限**：属于客户端本地特性的功能（本地 Obsidian 写入、第三方集成、图片代理、隐私偏好等），应当全面开放给所有开源使用者，不应当被当作付费筹码。
3. **算力多元化接入**：支持主流大语言模型服务商（包括 DeepSeek、Claude、OpenAI、Google Gemini 等），支持国内外各类高性价比、开源自建或聚合接口。
4. **消除付费打扰**：在客户端彻底解除所有对 Free 用户的本地权限锁定，提供纯净、无弹窗打扰的高效阅读体验。

| 功能特性 / 模块 | 官方原版 Free 限制 | 官方付费版权益 | 本定制版表现 (Custom 版) | 解锁实施机制 |
| :--- | :--- | :--- | :--- | :--- |
| **全部第三方集成** | 全部禁用置灰 | 开启 (Basic 及以上) | **完全解锁**：支持 Readwise、Obsidian、Cubox、Zotero、Instapaper、Outline、Eagle、qBittorrent、Webhooks | 客户端角色解锁 |
| **安全图片代理** | 登录后强制关闭 | 开启 (Basic 及以上) | **完全解锁**：自动处理微博/Pixiv/小红书等防盗链图片代理 | 客户端角色解锁 |
| **文章全文 AI 摘要** | 3 篇/天（频繁弹 402） | 30 篇 ~ 无限制 | **完全解锁**：无限制调用，直接走本地模型，永不弹窗 | 本地 CustomAIService 接管 |
| **全文与划词 AI 翻译** | 0 篇/天（完全不可用） | 300 篇 ~ 无限制 | **完全解锁**：无限制逐项翻译，完美保留 HTML/Markdown 排版 | 本地 CustomAIService 接管 |

| **时间线智能总结** | 限制调用 | 专属能力 | **完全解锁**：自动聚合未读订阅并调用本地模型完成速报总结 | 本地 CustomAIService 接管 |

| **私密订阅开关** | 开关禁用置灰 | 开启 (Basic 及以上) | **完全解锁**：允许将任何 Feed 自由设为私密源 | 移除表单限制 |

## 4. 功能限制层级与技术边界说明

为了让用户清晰了解系统的运行边界，特此说明各项特性的技术实现层级：

### 4.1 纯客户端限制（本版本已 100% 完整解锁）
核心业务逻辑完全运行在本地，官方后端并未介入校验：
- **第三方集成同步**：如 Obsidian 本地 Vault 文件直接写入、Readwise Token 直连、自定义 Webhook 发送；
- **图片防盗链代理**：官方图片代理节点本身不校验用户 Token，仅由客户端根据角色控制是否转换 URL；
- **UI 偏好与隐私设置**：纯本地展示开关；
- **私密订阅切换**：SQLite 本地数据库完整支持 `is_private` 字段。

### 4.2 混合限制（本版本已通过架构接管完整解锁）
官方云端施加了配额拦截，但客户端通过本地自建服务直接绕过云端：
- **AI 摘要、翻译、对话助手、模型切换**：直接由新增的 `CustomAIService` 接管，请求直连用户配置的第三方或私有大模型，彻底断开官方云端依赖。

### 4.3 服务端强校验限制（受官方中心化服务器控制）
以下数据与任务由官方中心化服务器（`api.follow.is`）集中管理，单纯修改客户端代码无法突破：
- **订阅源总数上限 (150 个)**：由服务端数据库与订阅创建接口强校验；
- **RSSHub 订阅总数 (30 个)**：官方后端校验。*替代方案：可自建 RSSHub 实例并使用标准 URL 订阅，按普通源处理*；
- **列表总数 (1 个)、收件箱总数 (1 个)、自动化规则数 (1 个)**：由服务端数据表及邮件转发网关统一控制；
- **云端加速抓取 (Boosts)**：依赖官方爬虫集群任务调度优先级。

## 5. 具体修改内容与实现概览

所有改动严格遵守 KISS 架构风格，杜绝多余抽象与冗余代码。改动明细汇总如下：

### 5.1 客户端角色单点覆写
- **路径**：`packages/internal/store/src/modules/user/store.ts`
- **实现**：在用户数据同步入口，将本地用户的 `UserRole.Free` 单点识别为 `UserRole.Pro`，一站式解锁所有第三方集成、图片代理与本地付费判定逻辑。

### 5.2 自定义 AI 服务核心类 (CustomAIService)
- **路径**：`packages/internal/store/src/services/custom-ai.ts`
- **实现**：
  - 同步解析本地存储中配置的 BYOK Provider；
  - 自动剥离模型名称中的前端冗余前缀（如 `openai/`、`custom/`），确保请求格式规范；
  - 支持 OpenAI 兼容规范与 Google Gemini 原生格式；
  - 基于 `ReadableStream` 与 SSE 协议实现流式对话通信（`streamChat`）；
  - 封装统一的摘要生成（`generateSummary`）与文本翻译（`translateText`）接口。

### 5.3 全链路接管与断开官方降级
- **AI 摘要**：`packages/internal/store/src/modules/summary/store.ts` 优先走 `CustomAIService`，出错时直接提示错误，严格禁止 fallback 到官方 `api().ai.summary`；
- **AI 翻译**：`packages/internal/store/src/modules/translation/store.ts` 全程使用本地配置的模型翻译；
- **AI 对话**：`apps/desktop/layer/renderer/src/modules/ai-chat/store/transport.ts` 拦截官方请求，改用本地流式 SSE 通信，会话标题直接由首句截取本地生成。

### 5.4 BYOK 设置界面增强
- **路径**：`apps/desktop/layer/renderer/src/modules/settings/tabs/ai/byok/ByokProviderModalContent.tsx`
- **实现**：
  - 允许填入自定义 Base URL 与 API Key；
  - 增加“拉取模型列表”功能，自动请求端点的 `/models` 接口并解析呈现；
  - 支持直接下拉选择已拉取的模型，或自由手动输入模型名；
  - 扩展 `UserByokProviderConfig` 类型定义，持久化存储 `availableModels`。

### 5.5 模型选择器交互与时序修复
- **路径**：`AIModelIndicator.tsx`、`useAIConfiguration.ts`、`useAIModel.ts`
- **实现**：
  - 移除单个模型时禁用下拉的逻辑死锁，支持始终展开菜单；
  - 下拉菜单底部增加“配置 AI 模型...”快捷跳转项；
  - 修复浮窗或窄屏下文字隐藏问题，确保模型名称与下拉箭头始终可见；
  - 同步优先从本地读取 BYOK 配置，杜绝初始渲染时拉取官方配置污染缓存。

## 6. 快速上手与配置指南

1. 打开应用，进入 **设置 (Settings) -> AI 选项卡**；
2. 找到 **BYOK (Bring Your Own Key)** 配置区域；
3. 点击 **添加服务商**：
   - **服务商**：选择 OpenAI、Google、DeepSeek 或 Custom（自定义兼容接口）；
   - **API Key**：填写你的服务商 API 密钥；
   - **API 地址 (Base URL)**：若为第三方中转或自建网关，填入完整地址（如 `https://api.deepseek.com/v1` 或自定义域名）；
   - 点击 **拉取模型列表**，在下拉菜单中直接选择所需模型（如 `deepseek-chat`、`gpt-4o` 等）；
4. 保存配置，即可在文章详情、划词工具栏以及右下角 AI 对话窗口中完整使用全部 AI 能力；
5. 进入 **设置 -> 集成 (Integration)**，可自由开启 Obsidian、Readwise 等全部第三方笔记与素材管理联动。

## 7. 编译与打包说明

本项目推荐通过 pnpm 结合 Turbo 进行依赖管理与编译：

```bash
# 1. 安装项目依赖
pnpm install

# 2. 编译桌面端渲染层与 Electron 主进程（开发验证推荐）
pnpm run build:electron-vite

# 3. 启动桌面端网页预览模式
cd apps/desktop && pnpm run dev:web

# 4. 启动 Electron 桌面调试窗口
cd apps/desktop && pnpm run dev:electron

# 5. 打包桌面端完整分发包
pnpm run build:electron
```
